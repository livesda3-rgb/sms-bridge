# Клиент 0.6 и Android 0.4

Клиент — статическая PWA из `docs/` на HTTPS, GitHub Pages main `/docs`. На iPhone требуется установка на экран «Домой» (iOS 16.4+). APK напрямую POST-ит зашифрованный Web Push в endpoint подписки; API-сервера проекта нет. Push-сервисы Apple/Google/Mozilla всё равно участвуют.

## Вход и привязка

В 0.6 пароль временно отключён по запросу пользователя. Новая установка создаёт пару ключей и атомарно сохраняет сейф и неэкспортируемый приватный CryptoKey в IndexedDB (`deviceAccess`, привязанный к vaultId). При обновлении 0.5 и старше требуется один ввод прежнего пароля: открывается существующий ключ и сохраняется для автоматического входа, записи и подписка не меняются. Сохранение ключа проверяет текущий vaultId в той же транзакции, чтобы не восстанавливать доступ после сброса. Автоблокировки при сворачивании нет; камера и QR-таймеры останавливаются. Шифрование записей сохраняется, но пароль больше не является барьером доступа: ключ хранится в том же браузере. Сброс удаляет ключ, историю и подписку.

APK генерирует приглашение: 32 случайных байта, срок 15 минут, хеш в своей SQLite-базе. После возврата подписки APK проверяет источник, публичный ключ, секрет, формат, endpoint и ключи. Пользователь видит имя получателя, подтверждает импорт, затем отдельно назначает SIM. Приглашение расходуется атомарно; повторное использование отклоняется. При смене подписки нужен новый код.

Основной перенос — два QR внутри приложений, содержащие JSON протокола v1. PWA декодирует кадры локально jsQR; Android использует ZXing. Веб-клиент генерирует ASCII JSON с Unicode escapes, чтобы имена без потерь читались Android. Камера останавливается при отмене, чтении, блокировке и уходе в фон; истёкший ответный QR скрывается. После сканирования требуется отдельное нажатие «Подключить уведомления» для системного запроса разрешения. Ручной ввод оставлен запасным вариантом. Не коммитьте реальные приглашения или подписки. Ключ VAPID остаётся в Android Keystore. Общего логина/пароля у устройств нет.

## JSON-протокол v1

Приглашение APK:

```json
{"version":1,"type":"sms-bridge-source","sourceId":"installation-uuid","name":"Домашний телефон","publicKey":"BASE64URL_UNCOMPRESSED_P256","pairingToken":"BASE64URL_32_RANDOM_BYTES","expiresAt":1800000000000}
```

Получатель → APK:

```json
{"version":1,"type":"sms-bridge-recipient","sourceId":"installation-uuid","publicKey":"SAME_VAPID_PUBLIC_KEY","pairingToken":"SAME_ONE_TIME_TOKEN","recipientId":"recipient-uuid","name":"Мой iPhone","subscription":{"endpoint":"https://web.push.apple.com/EXAMPLE","expirationTime":null,"keys":{"p256dh":"BASE64URL_P256","auth":"BASE64URL_16_BYTES"}}}
```

Обычный тестовый push:

```json
{"version":1,"type":"sms","id":"message-uuid","sourceId":"installation-uuid","simId":"profile-uuid","simName":"Личная SIM","sender":"BANK","body":"Пример сообщения","receivedAt":1800000000000}
```

Входящие SMS передаются с дополнительными полями `messageId`, `partIndex` (от нуля), `partCount` (1–100). `id = messageId + '-' + partIndex`. Часть содержит до 2000 байт JSON-экранированного текста; весь payload до 3993 UTF-8 байт. Деление по Unicode code point без обрезания символов, сборка независимо от порядка доставки. В метаданных каждой части одинаковы источник, SIM, отправитель, дата и количество частей. Пока не пришли все части, интерфейс показывает их количество. Старый формат без multipart-полей поддержан для тестового push.

Для каждого HTTP запроса создаются новые ECDH P-256 ключи и salt. Используется `Content-Encoding: aes128gcm`, TTL 86400, urgency high, VAPID ES256 с aud origin endpoint и exp +1 час. Редиректы запрещены. Разрешены только штатные push-хосты Google, Mozilla и Apple. Неизвестный push-провайдер требует отдельной проверки и изменения allowlist.

## Локальное шифрование

- RSA-OAEP 2048 / SHA-256 ключевая пара создаётся в браузере. Публичный JWK доступен service worker; приватный PKCS8 хранится только обёрнутым AES-256-GCM.
- Ключ обёртки получается из пароля PBKDF2-HMAC-SHA256, 600000 итераций, случайная соль 16 байт. IV 12 байт. Пароль не сохраняется.
- Каждый входящий push service worker шифрует новым AES-256-GCM ключом и случайным IV, AES-ключ оборачивает RSA-OAEP. В IndexedDB остаются шифртекст, обёрнутый ключ, ID/группа и время хранения. ID записи входит в AAD.
- При входе приватный ключ импортируется как non-extractable и используется в памяти сессии. При блокировке ссылка и расшифрованная история очищаются. Это не защита от вредоносного браузера, ОС или скомпрометированного кода сайта; очистка JS-памяти физически не гарантируется.
- Настройки подключения и метаданные хранения не шифруются. Предпросмотр уведомлений — явное согласие на текст вне парольного экрана. На домашнем Android эта схема не шифрует SMS-базу.

Источник сообщения проверяется по `sourceId`, поля ограничены по длине; вывод через textContent. История удаляет повторы по ID и хранит 200 групп сообщений. Изменение источника требует отключения прежнего. Удаление данных сайта теряет историю/ключи. Нет синхронизации, QR, смены пароля без сброса, автоматической перепривязки подписки или подтверждения доставки APK.

## Проверки

`npm ci && npm test` (Node 22+, JDK 17). Единственная npm-зависимость — fake-indexeddb для тестов; в веб-приложении внешних зависимостей нет. Проверяются известный вектор RFC 8291 и независимый Node-получатель, VAPID, недопустимые endpoint и ключи, Unicode/JSON при делении, пароль и повреждение данных, блокировка при незавершённой расшифровке, multipart и обработчик push. Это не реальный тест Safari или фонового Android.

Спецификации: [RFC 8291](https://www.rfc-editor.org/rfc/rfc8291), [RFC 8292](https://www.rfc-editor.org/rfc/rfc8292), [WebKit Web Push](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/).

## Кадры ответного QR

Приглашение Android остаётся одиночным JSON QR. Ответ PWA передаётся кадрами `SBQR1|sha256hex|index|count|chunk`, где index начинается с нуля, chunk — до 240 символов ASCII JSON (Unicode представлен escapes). Разделение только по первым четырём `|`. SHA-256 вычисляется по UTF-8 полной ASCII JSON строки. Максимум 16000 символов и 67 частей. Кадры меняются каждые 1600 мс; при блокировке и истечении срока таймеры останавливаются, QR очищается. Сканер Android принимает кадры непрерывно, отвергает смешение разных хешей и несовместимые части. После сборки работает прежняя проверка подключения. Хеш не является аутентификацией.
