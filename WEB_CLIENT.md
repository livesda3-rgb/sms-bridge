# Веб-клиент SMS Bridge 0.2

Статический PWA-клиент находится в `docs/`. Собственный сервер не нужен; браузер создаёт подписку у своего push-провайдера. Android-отправитель должен реализовать Web Push (RFC 8291 + VAPID RFC 8292). APK 0.1 этого ещё не делает.

## Публикация на GitHub Pages

В репозитории: Settings → Pages → Build and deployment → Deploy from a branch → `main` → `/docs` → Save. После завершения сборки используйте адрес, показанный GitHub. Папку `docs` можно целиком перенести на любой HTTPS-хостинг. Изменение домена требует новой подписки и привязки.

На iPhone: Safari → Поделиться → На экран «Домой», открыть установленное приложение, затем разрешить уведомления. Требуется iOS 16.4+. На Android — браузер с Web Push, например Chrome. Приватный режим не поддерживается как надёжное постоянное хранилище.

## Что работает

- Подписка Web Push с открытым VAPID-ключом домашнего устройства; экспорт параметров получателя в JSON.
- Service Worker принимает сообщения, проверяет схему и источник, сохраняет в IndexedDB и показывает уведомление.
- До 200 сообщений на устройстве, дедупликация по UUID сообщения, поиск, фильтр SIM, копирование текста и очистка.
- Текст уведомления скрыт по умолчанию; пользователь может включить предпросмотр.
- Офлайн-оболочка, демонстрация с вымышленными SMS и отдельная локальная проверка уведомления.
- Отключение подписки. При изменении подписки требуется повторно передать данные в APK.

Привязка одной установки клиента — к одному домашнему устройству. SIM различаются по `simId`. APK должен назначать получателю только разрешённые SIM: клиентский фильтр не является контролем доступа. Пять сохранённых SIM-профилей и маршрутизация будут реализованы на отправителе. Другие пользователи устанавливают свой экземпляр клиента и передают свои подписки.

## Контракт подключения v1

Домашний APK генерирует собственную пару P-256 VAPID, хранит приватный ключ только у себя и выдаёт:

```json
{"version":1,"type":"sms-bridge-source","sourceId":"stable-installation-uuid","name":"Домашний телефон","publicKey":"BASE64URL_UNCOMPRESSED_P256_PUBLIC_KEY"}
```

Клиент принимает JSON, по нажатию кнопки запрашивает разрешение, создаёт подписку и выдаёт:

```json
{"version":1,"type":"sms-bridge-recipient","sourceId":"stable-installation-uuid","recipientId":"browser-generated-uuid","name":"Мой iPhone","subscription":{"endpoint":"https://push-provider/...","expirationTime":null,"keys":{"p256dh":"...","auth":"..."}}}
```

Эти данные нужно локально импортировать в APK и явно назначить SIM. Не размещать подписки в репозитории, URL, аналитике или журналах. Привязка сейчас ручная; QR и подтверждение отпечатка ключа пока отсутствуют. Отправитель должен проверять endpoint: HTTPS, запрет localhost/локальных сетей, ограничение на разрешённые push-провайдеры; нельзя выполнять произвольные URL из импортированного JSON.

Содержимое зашифрованного Web Push:

```json
{"version":1,"type":"sms","id":"globally-unique-message-uuid","sourceId":"stable-installation-uuid","simId":"stable-local-profile-uuid","simName":"Личная SIM","sender":"BANK","body":"Текст SMS","receivedAt":1792050000000}
```

`receivedAt` — Unix milliseconds. Повторная отправка одного SMS использует тот же `id`; UUID должен быть уникален между всеми SIM и источниками. Нельзя использовать только номер слота или subId как вечный идентификатор SIM. Web Push ограничивает размер полезной нагрузки (обычно около 4 КБ с накладными расходами); отправитель должен явно обрабатывать слишком длинные SMS. Разбиение с повторной сборкой пока не реализовано.

Успешное создание подписки не означает успешной доставки: UI прямо предлагает передать подписку в APK. Подтверждения доставки на домашний телефон пока нет. При 404/410 push-провайдера APK должен отключить адрес получателя и запросить новую привязку.

## Хранение и ограничения

SMS находятся в IndexedDB этого браузера, без отдельного пароля/шифрования на диске; доступ защищён блокировкой телефона и изоляцией браузера. История не синхронизируется между устройствами. Удаление данных сайта или удаление PWA может удалить подписку и историю. Демо не попадает в историю. Нет аналитики, CDN или сторонних скриптов. В уведомлениях без предпросмотра отображается имя SIM, текст и отправитель скрыты.

## Проверки

`node --test tests/*.test.cjs` и `node --check docs/app.js`.

Проверены валидация протокола, короткие/буквенные отправители, Unicode, отбрасывание чужого источника, обработчик push и переход по уведомлению. Полный браузерный тест, реальная push-доставка на iPhone/Android, отключение подписки и долговременная фоновая работа требуют HTTPS-публикации и рабочего отправителя. Их успешность пока не подтверждена.
