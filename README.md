# SMS Bridge

Входящие SMS с домашнего Android → Web Push на iPhone или Android. Отдельного сервера для доставки нет: APK обращается к push-сервису браузера, PWA размещается на статическом HTTPS-хостинге.

## Статус: Android 0.4 / клиент 0.6

На Samsung S23 Ultra с Android 14 проверен приём OTP от буквенного отправителя Yandex, определение SIM и сохранение в системную SMS-базу. Экран был выключен, приложение свёрнуто. Это проверка диагностической версии 0.1, а не всей цепочки доставки.

В 0.2 реализованы Web Push RFC 8291/8292, VAPID-ключ Android Keystore, одноразовая привязка получателей с подтверждением в APK, до пяти сохранённых SIM-профилей, отдельное правило получателя для каждой SIM, отзыв доступа, очередь и повторы при сетевых ошибках. Неизвестная SIM по умолчанию не пересылает сообщения. Длинные SMS передаются несколькими пушами и собираются клиентом.

В клиенте 0.6: автоматический вход без пароля, локальная зашифрованная история с сохранённым на устройстве ключом, поиск, фильтр SIM и до 200 сообщений. Старая история сохраняется после однократного ввода прежнего пароля. Облачных учётных записей нет.

**Реальная Web Push-доставка APK → iPhone/Android пока требует проверки на устройствах.** HTTP 2xx означает принятие push-сервисом, не прочтение и не гарантированное сохранение клиентом.

## Обновление Android на Mac

1. Скачайте исходники репозитория: Code → Download ZIP (или `git pull`, если проект уже клонирован).
2. Откройте папку `android` в Android Studio, выполните Sync и Run на подключённом Samsung.
3. Собирайте под тем же пользователем macOS, что и 0.1: сохранится существующий debug-ключ, Android установит обновление с сохранением данных. Приложение удалять не требуется. Если раньше использовалась иная подпись, понадобится именно прежний ключ.

JDK 17, SDK 35, Android 10+. APK не публикуется с новым случайным ключом, несовместимым с установленной диагностической сборкой. Инструкция: [android/README_RU.md](android/README_RU.md).

## Первое подключение

1. На iPhone откройте [клиент](https://livesda3-rgb.github.io/sms-bridge/) в Safari, добавьте на экран «Домой» и запустите оттуда. В новой установке вход автоматический. При обновлении старого клиента введите прежний пароль один раз для сохранения истории.
2. В APK нажмите «Показать QR подключения». В установленной PWA нажмите «Сканировать QR с Android» и разрешите камеру. После чтения нажмите «Подключить уведомления». Одноразовый код действует 15 минут; часы устройств должны быть выставлены правильно.
3. PWA покажет несколько сменяющихся ответных QR. В APK 0.4 нажмите «Сканировать ответный QR с iPhone» и держите камеру на экране до завершения счётчика частей. Проверьте имя и подтвердите подключение.
4. Настройте активную SIM: имя, номер и нужный получатель. Можно назначить одного получателя нескольким SIM. Без правила пересылка выключена.
5. В APK отправьте тестовый push. Он проверяет интернет-доставку без запроса настоящего SMS. Затем проверьте обычное SMS и OTP, в том числе при выключенных экранах.

Данные привязки содержат секрет подключения и параметры доставки: передавайте их напрямую между своими устройствами по доверенному каналу. После импорта приглашение становится недействительным. Удаление получателя в APK очищает его очередь и правила; уже отправленные пуши не отзываются.

Камеры обрабатывают QR локально. Сторонние сайты-генераторы не используются. На iPhone сканируйте из установленной PWA, чтобы подписка создавалась в ней. Ручная передача JSON сохранена как запасной вариант.

## Ограничения

- Android 0.2 установлен на устройстве пользователя. QR в 0.3, камеры и полный маршрут доставки ещё требуют проверки на устройствах. Дизайн, защита входа в сам APK, USB-модем и подтверждение доставки клиентом — следующие этапы.
- MMS и исходящие SMS не реализованы. Пока это специализированный приёмник, не полноценная замена обычному мессенджеру.
- После перезагрузки Android требуется первое разблокирование. Принудительная остановка приложения, ограничения батареи и Doze могут задержать отправку. Очередь хранится до 24 часов (до 1000 частей); повторная доставка допускается и удаляется по ID на клиенте.
- ICCID доступен не всегда. Когда он скрыт, профиль привязан к subId, а не слоту. После сброса, удаления eSIM или замены SIM может понадобиться новое правило. Надёжное распознавание вернувшейся SIM на любом Android не гарантируется.
- Apple/Google/Mozilla push-инфраструктура необходима; собственный сервер в телефоне её не заменяет. Доступность доставки из конкретной сети/страны нужно проверить.
- Серверное подтверждение получения и синхронизация истории между клиентами отсутствуют. Неполностью доставленное длинное SMS показывается как незавершённое.
- В клиенте 0.6 пароль временно отключён по запросу владельца. Ключ расшифровки сохраняется в IndexedDB как неэкспортируемый CryptoKey; каждый, кто откроет приложение на этом устройстве, имеет доступ к истории. При включённом предпросмотре текст попадает в системные уведомления без ввода пароля. Очистка данных браузера удаляет ключи/историю; забытый пароль восстанавливается только сбросом клиента и повторной привязкой.
- APK хранит полученные SMS в системной и своей локальной базе; пароль клиента не шифрует домашний телефон. VAPID-ключ не экспортируется из Android Keystore. Сайт и браузер остаются доверенными компонентами.

## Проверки

`npm ci && npm test` — нужен Node 22+ и JDK 17 с `javac`. 17 тестов: Web Push по известному примеру RFC 8291 и независимое расшифрование Node, подпись VAPID, ограничения endpoint/ключей/размера, пароль/неверный пароль/порча шифртекста, блокировка во время расшифрования, сборка длинного SMS, валидация источника и уведомления.

При проверке текущей версии также выполнены компиляция всех Android-классов против SDK 35, упаковка manifest через AAPT2 и преобразование классов в DEX через D8. Полный Gradle build, Android UI, реальный JobScheduler и Safari Web Push должны быть проверены на устройствах. В тестах нет настоящих SMS, OTP или подписок.

Протокол и устройство безопасности: [WEB_CLIENT.md](WEB_CLIENT.md).

В 0.4 ответная подписка разбивается на части по 240 символов с SHA-256 всего сообщения. Камера остаётся открытой, повторные кадры не учитываются, порядок не важен. Старые APK не поддерживают многокадровый QR; обновите Android до 0.4 перед привязкой. Сервер и интернет для переноса QR не используются.
