## История и удаление

Обновление само ничего не удаляет, не перешифровывает и не переносит в localStorage.
Новый интерфейс читает настоящую историю через существующие BridgeDB/BridgeVault.
Демо-база из /beta/ не импортируется.

Только при явной команде удаления после подтверждения новые операции атомарно
удаляют выбранные записи и сохраняют `deletedMessagesV1` в существующем store
settings. Идентичность — источник + идентификатор логического SMS. Все уже
сохранённые сегменты составного SMS удаляются вместе. Поздние/повторные сегменты
фильтруются при чтении; новое SMS с новым ID от того же отправителя показывается.
Действие охватывает снимок выбранных сообщений, а не новые SMS, пришедшие во время
операции. Соседние ветки и настройки подключения не затрагиваются.

Ограничение сохранённого push-кода: повторный push удалённого SMS может снова
показать системное уведомление и сохранить зашифрованный сегмент, но 0.8.0 не
покажет его в истории. В 0.7.1 отметки удаления неизвестны: после отката такие
повторно доставленные сегменты могут появиться. Это не изменение формата старых
сообщений и не потеря подключения; для устранения потребовалось бы менять путь
обработки push, чего этот кандидат намеренно не делает.

Удаление пользователем необратимо для уже удалённых записей. Git не содержит
резервную копию истории/настроек iPhone. Миграции данных при установке нет.

## Обновление оболочки

Файлы нового интерфейса имеют неизменяемые пути /releases/0.8.0/.
Service Worker устанавливает весь комплект, проверяет метку версии HTML и только
затем активируется. Навигация обслуживается HTML из кэша этой сборки, в том числе
офлайн; фоновое стандартное обновление SW и кнопка обновления сохранены.
При незавершённом развёртывании установка нового SW отклоняется, старый остаётся.
Удаляются только старые sms-bridge-shell-* кэши, не базы/настройки и не кэши беты.
Для последующих версий нужны новый каталог ресурсов, метка HTML и имя кэша.
Файлы опубликованного каталога версии нельзя менять: исправление получает новую версию.

## Проверки и ограничения

Пройдены 32 теста: существующие проверки шифрования, БД, авторизации, формата SMS
и обработчика push; новые проверки хранения/удаления, DOM-интеграции с данными
0.7.1 и атомарного кэширования. DOM-тесты исполняют фактические скрипты кандидата
над тестовым IndexedDB и настоящим шифрованием. Проверены PIN при повторном
запуске/сворачивании, сохранение темы и статусов, рабочие настройки, массовые
действия, повторное открытие, свайпы/вертикальная прокрутка/отмена.
PushManager и Service Worker в DOM-тесте имитируются; тест удостоверяет отсутствие
вызовов subscribe/permission, но не подтверждает работу APNs на физическом iPhone.

Команда:
`node --test tests/release-*.test.cjs tests/sw.test.cjs tests/db.test.cjs tests/vault.test.cjs tests/app-auth.test.cjs tests/core.test.cjs`

Не проверены на устройстве: внешний вид интегрированных рабочих настроек в Safari,
реальная подписка iPhone, входящее SMS/push, холодный запуск PWA/перезагрузка iPhone
и задержка 3–5 секунд. Физическое устройство недоступно из среды подготовки.
Android-сборка не запускалась: Android и его протокол не менялись.

## Публикация и контроль

Публикация main требует отдельного подтверждения пользователя. До него основной
адрес остаётся на 0.7.1; ветка кандидата не запускает GitHub Pages.
Перед публикацией повторно сверить main и список изменений; сохранить бета-файлы.
После согласованного обновления на действующем iPhone проверить историю, тему,
PIN и подключение, получить SMS при открытом и закрытом PWA, затем повторить после
перезагрузки. Сравнить фактическое время доставки с текущими 3–5 секундами.
Не переустанавливать PWA, не отключать подписку и не очищать данные сайта.

## Откат

При критической ошибке вернуть только docs/index.html, docs/sw.js и
 docs/version.json из указанного коммита 0.7.1 отдельным коммитом, сохранив /beta/,
APK, каталог ресурсов 0.8.0 и прочие изменения репозитория. Старые корневые
JS/CSS уже сохранены. Клиент должен получить старый SW при доступной сети;
проверить успешную активацию и перезапуск, затем реальный push.
Ни unregister, ни очистка IndexedDB/localStorage не нужны. Формат данных остаётся
совместимым; сознательно удалённые пользователем SMS возвратом исходников не
восстановятся. Отдельно учитывать поведение повторных сегментов, описанное выше.
