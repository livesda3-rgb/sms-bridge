# Клиент 0.7 / Android 0.5 · 16.10.2026

Контрольная точка: `checkpoint/before-ui-2026-10-16`, commit `444bbacfb6ff52a7dffe638a0e15d957cc846f6c`. История не переписывалась, прежние исходники сохранены. Существующих APK, тегов и Releases на момент начала этого этапа не было; восстановить несохранённый APK из Git невозможно.

## Изменения

- Версионированные ресурсы PWA, загрузка оболочки без HTTP-кэша, ручная проверка и обновление. Service Worker, URL, область приложения и IndexedDB прежние; подписка не удаляется.
- Главный экран с SMS, поиск, SIM и непрочитанные, детали и копирование. Настройки вынесены в меню.
- Уведомления: скрытые, отправитель, полный текст. Старое значение preview сохраняет смысл.
- Необязательный PIN на 4 цифры, по умолчанию выключен. Сохранённая задержка после ошибочных попыток. PIN блокирует интерфейс, но не шифрует ключ браузерного хранилища. Это сознательно не заявляется как криптографическая защита или биометрия.
- Android: карточки получателей, отдельное назначение SIM, меню, установочный QR без секрета, локальная генерация QR, копирование и отправка ссылки через системный диалог.
- Диагностика фиксирует отсутствие SIM/правила/доступного получателя и постановку SMS в очередь. HTTP-ответ push-сервиса не называется подтверждением доставки клиенту.
- Светлая и тёмная темы. Android получил отдельную иконку сервера.

## Сохранение данных

Версии схем SQLite и IndexedDB не менялись. Ключи, получатели, настройки SIM, история и очередь не сбрасываются. Добавлены отдельные записи настроек для PIN, темы, прочитанности и режима уведомлений. PIN по умолчанию выключен. При обновлении клиента 0.5 старый пароль всё ещё нужен один раз для доступа к сохранённому ключу, затем включается автоматический вход.

## Проверка на устройствах

1. Установить Android 0.5 **поверх** имеющегося приложения, собирая тем же ключом на прежнем Mac. Не удалять старое приложение.
2. Клиент: меню → Приложение → Проверить обновление. Если старая версия ещё не имеет меню, открыть тот же адрес с `?update=20261016` и затем повторно открыть установленный клиент; не очищать данные сайта.
3. Сверить сохранённую историю и подключения. Выбрать получателя для SIM.
4. Отправить новое настоящее SMS при свёрнутом Android и выключенном экране. В диагностике проверить SIM/правило/очередь/ответ push-сервиса; на iPhone проверить уведомление и запись.
5. Проверить задержку/повтор после отсутствия интернета, длинное SMS, буквенного отправителя. Само получение на устройствах невозможно подтвердить автоматическими тестами здесь.

## Сборка и выпуск APK

GitHub Actions проверяет тесты и собирает **неподписанный** release APK как временный артефакт проверки, не как установочное обновление. Для установки нужен прежний ключ подписи с Mac владельца. Не публиковать keystore или пароль в Git. После успешной проверки устройства создать стабильные теги и Release и приложить подписанный APK. Доступный GitHub-коннектор позволяет сохранять коммиты/ветки, но не создавать теги/Releases, поэтому контрольная точка сохранена отдельной веткой.

Биометрия, ACK доставки, несколько получателей одной SIM и новые фильтры отправителя/текста не добавлены: им требуется отдельная архитектура/правила. Существующая схема «одна SIM → один получатель» сохранена.

## Выполненные проверки

28 автоматических тестов: криптография Web Push Java → независимый Node-получатель, QR JavaScript → Java, хранение/сброс/дедупликация, режимы уведомлений и авторизация. Java-исходники скомпилированы ECJ с Android API 35. В Firefox проверены первый запуск, меню, детали, PIN (установка, вход, перезапуск, отключение), обновление и офлайн-оболочка. Отдельно проверен переход со старого HTTP-кэша: идентификатор ключа, источник и зашифрованная история сохранились. Блокировка убирает также открытый диалог с текстом SMS.

Это не проверка камеры/приёма SMS на Samsung и не подтверждение работы новой версии в Safari на iPhone.
